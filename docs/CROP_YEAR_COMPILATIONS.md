# SRA Crop Year compilations

Farm Managers continue compiling monthly audits, and SRA Admins continue certifying each monthly report. SRA Admins can then combine the certified monthly snapshots into an immutable Crop Year compilation on Web and Mobile.

## Workflow

- **Web:** Audit Center → Crop Year Compilations.
- **Mobile:** SRA Audit Desk → calendar icon, or Monthly Audit History → Crop Year Compilations.
- Select a canonical Crop Year Cycle, such as `2026-2027`, and either All Block Farms or one Block Farm.
- Review the server preview: included months, certified report count, unique operations/fields/members, audited hectares, cost, and Block Farm totals.
- Choose **Compile Crop Year** to persist the snapshot. Saved compilations remain available below the preview.
- Web offers **Print / Save PDF**; Mobile offers **Export / Share PDF**. Both use the same server-generated, escaped report HTML and show source-report certification attribution.

Compilation and retrieval require a live connection. SRA actions are never placed in the offline mutation outbox.

## Accounting rules

1. Only database reports with status `CERTIFIED`, certification timestamp, and certifier identity contribute. Their canonical validation and existing snapshot integrity hash must pass.
2. Filter individual operation snapshots by their stored `cropYearCycle`, not the calendar year of the report month. A monthly report containing operations from different crop years contributes only the selected operations.
3. Older operations can use a report-level crop year only when it identifies exactly one unambiguous year. Ambiguous operations in a report identifying the selected year block compilation; no calendar-date inference is used.
4. Include all certified monthly versions: the existing monthly workflow can create incremental reports containing additional operations, so selecting only the newest version would omit earlier certified work.
5. Exact duplicate operation snapshots count once. Conflicting certified snapshots for the same operation ID reject compilation with HTTP 409 so the source inconsistency can be reviewed.
6. Count each farm/field combination once for hectares. Use that field's latest included reporting-month/certification snapshot. Do not sum its acreage once per monthly report. Member counts include the distinct member identities represented by included operations.
7. Reports are explicitly labelled **certified reports to date**. They do not declare the crop year complete, require twelve calendar months, or introduce a second monthly certification seal. Crop-year activity can span calendar years and carryover reporting months.
8. Saved compilations are immutable. Identical source content and scope return the existing compilation. New monthly certifications create a new content-based snapshot; older compilations remain unchanged.

## Database / Schema

New server-only collection: `crop_year_compilations/{compilationId}`. IDs have the shape `CYA-2026-2027-{contentHashPrefix}` and are generated by the API.

```js
{
  schemaVersion: 1,
  cropYearCycle: "2026-2027",
  blockFarmId: null, // null = all farms; otherwise one canonical farm ID
  status: "COMPILED",
  coverage: "CERTIFIED_REPORTS_TO_DATE",
  contentHash: "sha256...",
  compiledAt: "ISO timestamp",
  compiledByUserId: "02000001",
  compiledByName: "SRA reviewer",
  sourceReportCount: 12,
  operationCount: 120,
  duplicateOperationCount: 0,
  fieldCount: 10,
  memberCount: 10,
  blockFarmCount: 1,
  monthCount: 12,
  periods: ["2026-01", "..."],
  totalCost: 100000,
  hectaresAudited: 20,
  monthlySummaries: [/* month, farms, operation count, total cost */],
  farmSummaries: [/* farm identity, periods, fields, members, area, operations, cost */],
  sourceReports: [/* report ID, farm, month, version, certification identity/time,
                    selected operation count, source fingerprint */]
}
```

The database document does not duplicate all source operation snapshots. It retains the certified source references/fingerprints and computed summaries. The compilation and its `CROP_YEAR_AUDIT_COMPILED` audit event are created atomically in a transaction that reads the certified reports.

Direct client reads and writes are denied in `firestore.rules`. No existing monthly records require migration. Logical backups now include this collection under schema `2026-10-15`; archives with schema `2026-09-28` remain readable, treating the new collection as empty.

## Server / API

All routes require an active, onboarding-complete SRA Admin on an allowed platform. Farm Members, Farm Managers, and Super Admins are denied these routes.

| Method | Route | Purpose |
|---|---|---|
| GET | `/api/crop-year-compilations/options` | Crop years and farms represented by certified reports |
| GET | `/api/crop-year-compilations/preview?cropYearCycle=2026-2027&blockFarmId=` | Authoritative current aggregate |
| POST | `/api/crop-year-compilations` | Compile using only `cropYearCycle` and optional `blockFarmId` |
| GET | `/api/crop-year-compilations?cropYearCycle=2026-2027&blockFarmId=&cursor=...` | Saved history, 20 entries per page |
| GET | `/api/crop-year-compilations/:id/print` | Escaped printable HTML in the authenticated JSON envelope |

Clients cannot supply report IDs, source arrays, computed totals, compiler identity, or status as authoritative fields. The service derives them from authenticated identity and stored certified reports. Content-based identity makes lost-response retries safe.

Queries are bounded to 2,000 certified source reports per selection and compiled documents to 800 KiB. Exceeding either limit returns an explicit HTTP 413; source data is not silently truncated. A Block Farm selection narrows the compilation query. History uses a scope-validated cursor. Preview/options are read live rather than served from the generic scoped response cache.

## Deployment and validation

Deploy the API and clients, and deploy the updated Firestore indexes/rules using the normal authorized release process. The new indexes support:

- `crop_year_compilations`: `cropYearCycle`, `blockFarmId`, `compiledAt DESC`.
- `audit_reports`: `status`, `blockFarmId` for scoped certified-source reads.

No rules, indexes, remote databases, or EAS builds were deployed by this implementation task.

Behavioral coverage lives in `server/tests/crop-year-compilation.test.js`. It tests crop-year identity across calendar years, mixed-year monthly reports, incremental versions, deduplication/conflicts, unique hectares, integrity/attribution, permissions, empty selection, replay/new snapshots, API totals, print escaping, and legacy-backup compatibility. Web and Android production bundles must also pass.

Perform a deployed browser/device smoke test for selection, compilation, reopening history, print/PDF sharing, reconnect behavior, and role denial. A bundle export alone does not validate a native PDF/share sheet.
